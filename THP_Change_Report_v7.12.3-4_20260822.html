v7.12.3 — Resume Fitment fixes  |  22 Aug 2026 v7.12.3

CR TitleWhat ChangedTest Status
"Score Resume Fitment" — Load failed Root cause: resumes uploaded through THP's own new upload feature (v7.12.2) are stored with their SharePoint webUrl as ResumeLink — an interactive viewer page meant for browser navigation, not a raw file stream. extractResumeText() was doing a plain fetch() on that URL, which has no session/auth context and fails outright — the exact "Load failed" signature from the CORS bug fixed earlier this session, but a different root cause this time. Fixed by resolving SharePoint URLs through Graph's /shares endpoint (the documented way to turn any webUrl into a fetchable DriveItem) and downloading via its authenticated /content endpoint instead. Azure-blob resumes (Portal-sourced) are unaffected by this specific fix, but needed a separate one — see next row. Verified
Confirmed the URL-type routing logic picks the correct path for both a sample SharePoint URL and a sample blob URL. The live Graph /shares round-trip wasn't independently re-tested (needs a real uploaded resume + live session) — recommend trying Score Resume Fitment again on the resume you just uploaded.
Portal-sourced resumes — same failure, different cause While fixing the above, found that Portal-sourced resumes (Azure Blob Storage, SAS-scoped URLs) would have hit the same "Load failed" error for a different reason: the storage account's CORS rule (added earlier this session for video interview uploads) only allowed the Portal's own two origins, not THP's GitHub Pages origin — so THP could never have fetched a Portal-sourced resume for scoring either, CORS-fixed webUrl issue or not. Added a second CORS rule permitting GET/HEAD from THP's origin. Verified
Confirmed via az storage cors list — two rules now present on talentgatewaysa: the Portal's origins (read/write) and THP's origin (read-only). Purely additive, nothing removed.
Resume Fitment Vs JD missing from summary/PDF Confirmed: neither the AI-generated interview summary nor the exported PDF report ever referenced the Resume Fitment Vs JD score — it only ever showed in the candidate detail modal and the Interview Guide's AI-Assisted Signals block. Added it to both: the AI Summary prompt now receives the score + recommendations as data and is asked to reference it in one line (kept clearly distinct from the existing rule against the AI inventing the interview's own deterministic fitment score — that rule now explicitly says why, so it doesn't accidentally suppress the resume one too). The exported PDF gets a new "Talent+ Gateway — AI Signals" section showing both Resume Fitment Vs JD and the AI Video Interview score, positioned before the manual Evaluation Scores / Interview Fitment Score section so the two "fitment" numbers are never confused for one another. Verified
Confirmed with mock data: the AI Summary prompt correctly includes the resume fitment line, and the exported PDF's captured HTML includes the new section with correct values, without disturbing the existing Interview Fitment Score block.

v7.12.4 — Candidate resume self-upload invite  |  22 Aug 2026 v7.12.4

CR TitleWhat ChangedTest Status
Invite to Upload Resume v7.12.2 added a recruiter-side direct upload (pick a file from your own computer) — this adds the other half: a candidate-facing invite, mirroring "Invite to AI Interview" exactly. New button "📧 Invite to Upload Resume" in the candidate detail modal (shown only when there's no resume on file yet), which sets ResumeUploadInvited and drafts an email with a link to a new Portal page (talent-gateway, separate repo) where the candidate verifies their email via OTP and uploads their own file — landing straight in the same ResumeLink field. Gated the same way the AI interview invite is: only the specific (email, vacancy) pair a recruiter invited can use the link. Verified
Confirmed both resume buttons ("Upload Resume" and "Invite to Upload Resume") render side by side and only the invite one shows once a resume already exists. Portal side (new page + two API routes) verified via clean tsc and production build. Not yet tested end-to-end against a live invite — needs the new column added first.
