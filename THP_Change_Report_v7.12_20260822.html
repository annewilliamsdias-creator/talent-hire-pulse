v7.12 — Post-launch fixes and dashboard visibility  |  22 Aug 2026 v7.12

CR TitleWhat ChangedTest Status
Video interview viewer — can't close Real bug, not a preference: the AI Video Interview popup used the app's generic small dialog (.mc, max-width 460px, no max-height or scroll). A video player + scores + full transcript reliably grew taller than the screen, pushing the Close button below the visible area with no way to scroll to it or click outside to dismiss. Rebuilt viewVideoInterview() as its own dedicated overlay (new #viewint-overlay), matching the Interview Guide's existing overlay pattern exactly: fixed header with the video's title/date, a maximise (⛶) toggle, and a Close button that's always in the header, never dependent on scroll position. Click-outside-to-close also works now. Verified
Rendered with mock interview data locally: confirmed Close returns to the dashboard cleanly, confirmed Maximise expands to full-screen and back. The old trap (content taller than viewport hiding Close) can't recur — the new body div scrolls internally under a header that never moves.
Transcript auto-record onto Page 3 The AI interview's per-question transcript now auto-fills into the matching question's note field on the Interview Guide's Role Questions page (Page 3), the moment the page is opened for a candidate who has completed an interview — not just displayed as a suggestion, but actually written into igEvalData[code].notes so it's captured even if the recruiter never touches the field, and persists on the next "Save Notes" the same way a manually-typed note would. A teal "🎥 auto-recorded from AI interview" tag marks which notes came from this, and typing over any of them permanently overwrites — the auto-fill only ever applies to a still-empty note. Note fields upgraded from single-line inputs to small textareas so real transcript text fits and wraps. Verified
Confirmed with mock data: an unanswered question correctly stays blank (no bogus transcript), an answered one is written into igEvalData immediately (checked via console, not just visually). Caveat carried forward from the design, not new: matching is positional — combined question index in the AI interview must line up with this JD's q1-q10/aq1-aq5 order, since the Portal's copy of these questions is manually maintained separately from the JD Library. If a JD's questions are ever reordered without updating the Portal's copy, this mapping silently drifts. No way to detect that from THP's side.
Score reasoning — strengths / watch-outs The AI video interview previously only showed a numeric score and one narrative paragraph. The Portal's scoring prompt now also returns specific "Strengths" and "Watch-outs" bullets (see talent-gateway's own change history for the prompt change) — rendered here in three places: the Interview Guide's Evaluation page (AI-Assisted Signals block), the new video interview overlay above, and nowhere else duplicated. Blank/hidden entirely for any interview scored before this change (old data has no strengths/watchOuts fields — code checks for their presence before rendering, no error either way). Verified
Rendered with mock strengths/watchOuts arrays in both locations; confirmed graceful blank when absent (tested by omitting the fields from mock data).
"View" added to Home Dashboard rows The Action Queue table on the Home Dashboard only had "Update" — a recruiter had to go to All Records to open the read-only candidate view (and, per the item below, to reach the Gateway status/invite action) from the dashboard itself. Added a "View" button next to Update, reusing the exact same openBtn(this,'view') handler All Records already uses. All Records keeps both buttons unchanged. Verified
Clicked live in the local test build — opens the same candidate modal as All Records' View.
Gateway status line on dashboard rows Added a compact status line under each Action Queue candidate's name/code: a colour dot (grey = not invited, gold = invited/awaiting, teal = interview received), the three scores as text (🔍 Resume Fitment, 🎥 AI Interview, 📋 Recruiter Interview — this last one computed live from igEvalData, converted to the same /10 scale as the other two for a fair side-by-side read, not stored anywhere new), and — only when not yet invited — a small 🎥+ button that calls the existing inviteToVideoInterview() directly from the dashboard row. Blank entirely for any candidate with no vacancy code, matching the gating used everywhere else Gateway data shows. Verified
Confirmed against mock data: dot colour, all three scores, and the recruiter-interview average (checked the arithmetic against the mock's manual scores) all matched expectations; invite button fires correctly and disappears once invited.
Resume Fitment — visible "not yet scored" state The score already displayed once computed, but a candidate with a resume and no score yet showed nothing at all — easy to read as broken rather than "hasn't been scored." Added a visible prompt in the candidate detail modal when a resume link exists but no fitment score does yet, pointing at the existing "Score Resume Fitment" button below it. No change to the scoring flow itself — still a manual, one-click action, by design (AI-cost-conscious). Verified
Tested by clearing a mock candidate's fitment data and confirming the prompt renders exactly where the score normally would.
Vacancy filter on Home Dashboard Added a Vacancy dropdown to the dashboard's filter bar, alongside the existing Recruiter/Client filters — labelled by Role (Designation) plus Company, not the raw vacancy code, and populated only from vacancies that actually have candidates tagged to them (not every historical vacancy ever created). Filtering by it narrows the same hfMD set every other dashboard filter already narrows — Action Queue, Upcoming Interviews, Joining in Progress, and the KPI counts all respect it. Verified
Confirmed dropdown renders "Role — Company" labels correctly and the Clear button resets it along with the others.

Not a code change

Two of Anne's twelve items were answered directly rather than built: (1) whether OTP re-verification is still needed given the recruiter already emailed the registered address — yes, kept as-is, since the interview link is shared per-vacancy rather than per-candidate and OTP is what stops anyone else with the link from impersonating an invited candidate. (2) A "trigger to recruiter on submission" — interpreted as satisfied by the dashboard status dot above (a visible "received" state) rather than a separate email/push notification; flagged to Anne as an interpretation she can correct if she actually wants a real notification.
