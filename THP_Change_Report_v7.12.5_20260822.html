v7.12.5 — Automated invite emails (no more mailto:)  |  22 Aug 2026 v7.12.5

CR TitleWhat ChangedTest Status
Invite emails no longer use mailto: Anne's exact complaint: "Invite to interview opens the mailbox — how will it auto identify which mailbox to use — recruiters use Outlook web, I use Outlook desktop, but it opened the Mac Mail app." Root cause: mailto: links have zero control over which mail client or sending identity handles them — that's decided entirely by the OS default on whichever machine clicked the button, different per recruiter, and with no way to make it consistently "come from Talent+ Gateway." Fixed by having THP call a new endpoint on the Portal (talent-gateway, separate repo — /api/notify/invite) that sends the email server-side through the exact same Azure Communication Services sender ("Talent+ Gateway") that already sends every OTP verification email — same sender identity Anne referenced as "the original email." Both "Invite to AI Interview" and "Invite to Upload Resume" now use this. If the send fails for any reason (key not yet configured, network issue, Portal API down), the button falls back to the old mailto: draft rather than silently failing — the invite flag itself is always set first regardless, so a failed email never blocks the actual invite. Verified live
Called the live Portal endpoint directly (curl) with a real email address — confirmed a real email was delivered from the Talent+ Gateway sender. Also confirmed the authorization check (wrong key → 401), CORS headers are present and scoped to this app's exact origin, and a bad recipient correctly surfaces as a clean error rather than a silent failure. One transient issue found and resolved during testing: the very first requests after deploying returned 404 despite the route existing in the build — an edge/routing cache serving a pre-deploy 404 for that exact URL; a full app restart cleared it and the route has responded correctly on every request since (bare URL, no cache-busting needed).
